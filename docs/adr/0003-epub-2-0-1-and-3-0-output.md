# ADR 0003: EPUB 2.0.1 と EPUB 3.0 を、同じ入力から版を選んで出し、版ごとに必須の構成で作る

ステータス: 採択→ADR 0019

## 文脈

EPUB の版によって、パッケージ文書（OPF）の書き方、目次の持ち方、本文の文書の形式が違う。

- EPUB 2.0.1：OPF 2.0.1 のパッケージ文書（`version="2.0"`）、目次は NCX（必須）、本文は XHTML 1.1
- EPUB 3.0：パッケージ文書は `version="3.0"`、目次はナビゲーション文書（必須）、本文は XHTML の構文で書いた HTML5、`dcterms:modified` が必須

一方、どちらの版も、zip の先頭に圧縮しない `mimetype` を置き、`META-INF/container.xml` からパッケージ文書を指す点は同じである。
epubize で作るのは日本語の縦書きの小説が主になる。

## 実装すること

- 呼び出し側は、一つの入力（書誌情報、本文、スタイルシート、画像）と、出す版（`"2.0.1"` か `"3.0"`）を渡す
- どちらの版でも、次を作る
  - zip の最初の項目として、圧縮しない `mimetype`（内容は `application/epub+zip`、余分な項目を付けない）
  - `META-INF/container.xml`
  - パッケージ文書、本文の文書、スタイルシート、画像を、決まったディレクトリ（`OEBPS/`）の下に置く
  - 本文の文書は、呼び出し側が渡した XHTML の本文（`body` の中身）を、版に合った文書の形で包んで作る
- EPUB 2.0.1 では、次を作る
  - OPF 2.0.1 のパッケージ文書。`dc:identifier`、`dc:title`、`dc:language` を必ず書く
  - NCX（`toc.ncx`）の目次。spine の `toc` 属性から指す
  - 本文は XHTML 1.1 の DOCTYPE を持つ文書とする
  - 表紙の画像は `<meta name="cover" content="…">` で示す
- EPUB 3.0 では、次を作る
  - `version="3.0"` のパッケージ文書。`dc:identifier`、`dc:title`、`dc:language`、`dcterms:modified` を必ず書く
  - ナビゲーション文書（`nav.xhtml`、`properties="nav"`）の目次
  - EPUB 2 にしか対応しないリーダーのため、NCX も作り、spine の `toc` 属性から指す
  - 本文は XHTML の構文で書いた HTML5 の文書とする
  - 表紙の画像は `properties="cover-image"` で示す
  - 頁送りの向き（`page-progression-direction`、`ltr` か `rtl`）を spine に書けるようにする。縦書きの本では `rtl` にする
- 目次は入れ子にできるようにする（章の下に話を並べる、など）
- 画像は、どちらの版でも中核の形式（JPEG、PNG、GIF、SVG）を扱う
- 書誌情報の文字列は、XML として正しくなるように実体参照に直して書く

## 実装しないこと

- 固定レイアウト（Fixed Layout）は扱わない
- EPUB 3.1 以降、EPUB 3.3 に固有の機能は扱わない
- EPUB 2.0.1 で `page-progression-direction` を書くことはしない。2.0.1 の仕様にない属性であり、検証で誤りになるため。縦書きは呼び出し側のスタイルシートで行う
- 音声、動画、メディアオーバーレイ、スクリプト、フォントの埋め込みの暗号化（難読化）は扱わない
- 本文の XHTML が正しいかの検査は、この ADR では行わない。呼び出し側が正しい XHTML を渡すものとする
- 特定のリーダーや配信サービスに固有の拡張（Kindle の独自のメタデータなど）は持たない

## テスト設計

- 実装するときに、次をテストする
  - zip の最初の項目が、圧縮しない `mimetype` で、内容が `application/epub+zip` であること
  - 版ごとに、パッケージ文書、目次（NCX、ナビゲーション文書）、本文の文書が、必須の要素と属性を持つこと
  - 入れ子の目次、表紙、頁送りの向き、書誌情報の実体参照
- 作った EPUB を、公式の検証ツール EPUBCheck で、版ごとに検証し、誤りも警告もないことを CI で確かめる
- フィクスチャは合成データとする

## トレードオフ

- 一つの入力から両方の版を出すため、片方の版にしかない機能は、もう片方では無視するか、別の手段で表すことになる
- EPUB 3.0 にも NCX を入れるため、出力は少し大きくなる。その代わり、古いリーダーでも目次が使える
- 本文の XHTML を検査しないため、呼び出し側の誤りは EPUBCheck で初めて分かる
