# ADR 0008: 目次を、ディレクトリの入れ子の下に、文書の中のすべての見出しを入れ子の節として続けて作る

ステータス: 採択

## 文脈

ADR 0006 では、`body/` のファイル一つを目次の項目一つとし、文書の中の見出しから項目を作らないとした。
目次の入れ子は、ディレクトリの入れ子（部、章）で表す。

しかし、一つの章の中に節や項を立てる原稿では、章の中の構成が目次に出ない。
節ごとにファイルを分ければ目次に出るが、短い節まで分けるのは書きにくい。
そこで、ディレクトリの構造（部、章）はそのまま目次の上の段とし、その下に、各文書の中の見出しを節として入れ子で続ける。

この ADR は、ADR 0006 の次の箇所を改める。ほかは ADR 0006 と ADR 0007 のとおりとする。

- 目次の「`body/` の文書は、一つのファイルを目次の一つの項目とする。ファイルの中の見出しから、さらに項目を作ることはしない」
- 実装しないことの「文書の中の見出しから、目次の項目や、文書の分割を作ることはしない」のうち、目次の項目を作らないこと

## 実装すること

### 本を表す値

- 章（`Chapter`）に、その章の文書の中の節の並び `sections` を持てるようにする

  ```ts
  interface Section {
    title: string;
    /** 章の本文の中の、節の見出しの id */
    id: string;
    children?: Section[];
  }
  ```

- `buildEpub` は、章の項目の子として、まず `sections` を、次に `children`（子の章）を、この順で目次に書く。節の行き先は `<章の文書>#<id>` とする
- `buildEpub` は、`sections` を持つ章が本文を持つこと、`id` が空でなく、本文の中にその `id` を持つ要素があることを調べ、満たさなければ例外とする

### 目次の構成

- 目次の上の段は、ADR 0006 のとおり、ディレクトリの入れ子（`index` の扱いを含む）と、ファイル一つを一つの項目とする並びで作る
- 各文書の項目の下に、その文書の中の見出しを、節として入れ子で続ける
  - 対象は、文書の題名に使った見出し（文書の最初の見出し）を除く、すべての `h1` から `h6` とする
  - 見出しの入れ子は、レベルで決める。ある見出しは、それより前にある、レベルの数がより小さい見出しのうち最も近いものの子とする。そのような見出しがなければ、文書の項目の直下に置く
  - レベルが飛んでもよい（`h2` の次に `h4` があれば、`h4` は `h2` の子とする）
- ディレクトリの `index` の文書の節は、そのディレクトリの項目の下に、子の項目より前に置く。読み順と目次の順をそろえるためである
- 奥付の節も、奥付の項目の下に置く。表紙は目次に入れないため、表紙の見出しは節にしない
- 脚注の欄（`<div class="footnotes">`）の中の見出しは節にしない
- 節の題名は、文書の題名と同じ規則（ルビの読みと括弧、脚注の参照を除き、HTML の空白をまとめる）で決める。空になる見出しは節にしない

### 見出しの id

- 見出しに `id` があれば、それを節の行き先に使う
- なければ、文書ごとに `sec-1`、`sec-2` … を、文書の中の順に付ける。本文に同じ `id` がすでにあれば、その番号を飛ばして次の番号を使う
- 付けた `id` は、本文の見出しの要素に書き出す

## 実装しないこと

- 見出しの位置で文書を分割することはしない
- 節にする見出しのレベルを設定で選ぶことはしない。すべての見出しを節にする
- 見出しの番号付け（`1.1` など）はしない
- 表紙の見出しを目次に入れることはしない
- 節の `id` が、ほかの文書からのリンクの断片識別子と合うかは確かめない

## テスト設計

- 見出しのレベルからの入れ子（レベルが飛ぶ場合、最初の見出しより小さいレベルが後に来る場合を含む）
- 文書の題名に使った見出しが節にならないこと
- 見出しの `id` を使うこと、なければ `sec-<番号>` を付けること、本文にある `id` を避けること
- `index` の節が、ディレクトリの子の項目より前に来ること
- 奥付の節が目次に入り、表紙の見出しが入らないこと
- 脚注の欄の中の見出しと、空の見出しが節にならないこと
- 節の題名から、ルビの読みと脚注の参照が除かれること
- `buildEpub` が、節を NCX とナビゲーション文書に、文書の中の断片識別子付きの行き先で書き、`playOrder` を目次の順に振ること
- `buildEpub` が、本文のない章の `sections`、空の `id`、本文にない `id` を例外にすること
- フィクスチャから作った EPUB が、節を含めて EPUBCheck を通ること

## トレードオフ

- 目次が深く長くなる。見出しの多い原稿では、リーダーの目次が読みにくくなることがある。必要になったら、レベルを選ぶ設定を別の ADR で決める
- 見出しに `id` がない原稿では、EPUB の本文に `sec-<番号>` の `id` が加わる。見出しを足したり減らしたりすると、後ろの見出しの `id` が変わる
- 目次の項目の行き先に断片識別子が入るため、NCX の `playOrder` は同じ文書の中でも節ごとに別の値になる
