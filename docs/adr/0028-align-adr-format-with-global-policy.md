# ADR 0028: ADR の書式を作者の全リポジトリに共通する方針に合わせ、参考文献の節と破棄のステータスを加える

ステータス: 採択→CI での adr-guard links の扱いは[ADR 0029](0029-check-adr-links-in-ci.md)

## 文脈

作者の全リポジトリに共通する方針（グローバルの CLAUDE.md）が改められ、ADR の書式について次のことが定められた。

- 節は「文脈」「実装すること」「実装しないこと」「テスト設計」「トレードオフ」「参考文献」とする。参考文献には仕様の調査に使った文献を書き、ない場合は「なし」と書く
- データ構造やアルゴリズムを変える場合は、その節も立てる。仕様の検討のログとして残したほうがよいことがあれば、節を立てる
- ステータスは「採択」「採択→変更後の ADR 番号」「採択→○○（変更部分）は ADR NNNN」「提案」「却下」「破棄」などで書く
- ADR を破棄する場合は、ステータスを「破棄」にして、理由を `docs/specifications.md` に書く
- ADR を作った後と、ドキュメントを更新した後は、`adr-guard links --fix` で ADR のリンクを確かめ、直す

このリポジトリの今の状態は次のとおりである。

- 参考文献の節を持つのは [ADR 0027](0027-update-adr-guard-to-v0-8-2.md) だけで、[ADR 0001](0001-epub-builder-library.md) から [ADR 0026](0026-update-adr-guard-to-v0-8-1.md) は持たない。これらはコミット済みで、ステータスの行とリンクのほかは変えられないため、節を足せない
- ステータスの書き方は [ADR 0025](0025-update-adr-guard-to-v0-8-0.md) で決めており、「提案」「採択」「却下」「採択→ADR NNNN」「採択→<置き換えた部分>は ADR NNNN」だけを認める。ステータスを調べるテスト（`test/adr.test.ts`）は「破棄」を認めない
- ADR を破棄したときの扱いは [ADR 0020](0020-adr-workflow-and-adr-guard.md) で決めており、経緯と理由を `docs/specifications.md` に書き、番号を欠番にするとしている
- tett23/adr-guard（v0.8.2）は、ステータスの値「破棄…」を、採択されずに取りやめた状態（Discarded）として解釈する

## 実装すること

### ADR の節

- これから作る ADR の節は、次の順とする。参考文献は最後の節とする

| 節             | 中身                                                         |
| -------------- | ------------------------------------------------------------ |
| 文脈           | 決定が要る理由、前提、調べて分かったこと                     |
| 実装すること   | 決定の中身                                                   |
| 実装しないこと | 決定の範囲の外にあるもの                                     |
| テスト設計     | 決定を確かめるテストと、自動のテストを書けない場合の確かめ方 |
| トレードオフ   | 決定によって失うもの、負担                                   |
| 参考文献       | 仕様の調査に使った文献。ない場合は「なし」と書く             |

- 次の節は、必要なときに、テスト設計より前に立てる
  - データ構造やアルゴリズムを変える場合：その節（「データ構造」「アルゴリズム」など）
  - 仕様の検討のログとして残したほうがよいことがある場合：「検討の記録」などの節
- 参考文献を求めるのは、[ADR 0027](0027-update-adr-guard-to-v0-8-2.md) 以降の ADR とする。[ADR 0001](0001-epub-builder-library.md) から [ADR 0026](0026-update-adr-guard-to-v0-8-1.md) はコミット済みで節を足せないため、求めない

### ステータス

- ステータスの書き方は次のとおりとする。[ADR 0025](0025-update-adr-guard-to-v0-8-0.md) の書き方に「破棄」を加えたものである

| ステータス                         | 意味                                         |
| ---------------------------------- | -------------------------------------------- |
| `提案`                             | レビューを待っている                         |
| `採択`                             | 決定として有効                               |
| `採択→ADR NNNN`                    | 採択したが、全体を ADR NNNN に置き換えられた |
| `採択→<置き換えた部分>は ADR NNNN` | 採択したが、一部を ADR NNNN に置き換えられた |
| `却下`                             | レビューで採択しなかった                     |
| `破棄`                             | 採択されずに取りやめた                       |

- ADR の参照には、これまでどおりリンクを付ける（`採択→[ADR NNNN](NNNN-....md)` など）

### ADR の破棄

- ADR を破棄するときは、ステータスを `破棄` にし、経緯と理由を `docs/specifications.md` の「破棄した ADR」の節に書く
- 破棄した ADR のファイルは残す。番号は、その ADR が使ったままとし、欠番にしない。[ADR 0020](0020-adr-workflow-and-adr-guard.md) の「番号は欠番にする」を、この ADR で置き換える

### 手順

- ADR を作った後と、ドキュメント（`README.md`、`docs/specifications.md`、`CLAUDE.md`）を更新した後に、`adr-guard links --fix` を実行してリンクを付け、`adr-guard links` で確かめる

### 置き換えと文書の更新

- [ADR 0020](0020-adr-workflow-and-adr-guard.md) のステータスを `採択→adr-guard のバージョン、hook と CI のオプションは[ADR 0025](0025-update-adr-guard-to-v0-8-0.md)、ステータスの書き方と ADR の破棄の扱いは[ADR 0028](0028-align-adr-format-with-global-policy.md)` にする
- [ADR 0025](0025-update-adr-guard-to-v0-8-0.md) のステータスを `採択→adr-guard のバージョンは[ADR 0026](0026-update-adr-guard-to-v0-8-1.md)、ステータスの書き方は[ADR 0028](0028-align-adr-format-with-global-policy.md)` にする
- リポジトリの `CLAUDE.md` の「ADR」の節に、節の順と参考文献、立ててよい節、破棄のステータスと扱い、`adr-guard links --fix` の手順を書く
- `docs/specifications.md` の「破棄した ADR」の節の説明を、破棄の扱いに合わせて書き換える

## 実装しないこと

- [ADR 0001](0001-epub-builder-library.md) から [ADR 0026](0026-update-adr-guard-to-v0-8-1.md) に参考文献の節を足すことはしない。コミット済みの ADR の本文は変えられない
- ステータス `廃止`（adr-guard の Deprecated）を加えることはしない。方針に挙がっていないため。必要になったら別の ADR で決める
- ステータスの行の英語の見出し（`Status:`）は使わない
- CI で `adr-guard links` を実行することはしない。この ADR では手順として決めるにとどめる
- 参考文献の中身（文献が十分か）を自動で調べることはしない

## テスト設計

- 先に `test/adr.test.ts` に次を加えて失敗させてから、テストの判定を直す
  - ステータスの判定が `ステータス: 破棄` を認めること。`ステータス: 破棄（理由）` のような書き方は、これまでどおり認めないこと
  - [ADR 0027](0027-update-adr-guard-to-v0-8-2.md) 以降の ADR が、「文脈」「実装すること」「実装しないこと」「テスト設計」「トレードオフ」「参考文献」の節をこの順に持ち、参考文献が最後の節で、中身が空でないこと（「なし」は認める）
  - 節の順の判定が、必須の節の間に別の節（「データ構造」「検討の記録」など）があっても通ること、参考文献のない ADR と、参考文献が最後でない ADR を違反にすること
- 実装の後に、次を実際に動かして確かめる
  - `adr-guard links` と `adr-guard check-status` が終了コード 0 で終わること
  - [ADR 0020](0020-adr-workflow-and-adr-guard.md) と [ADR 0025](0025-update-adr-guard-to-v0-8-0.md) のステータスの行の変更を、pre-commit hook が許可すること

## トレードオフ

- [ADR 0026](0026-update-adr-guard-to-v0-8-1.md) までと [ADR 0027](0027-update-adr-guard-to-v0-8-2.md) 以降で書式が違う。[ADR 0026](0026-update-adr-guard-to-v0-8-1.md) までの ADR を読むときは、参考文献の節がないことを前提にする
- 破棄した ADR のファイルを残すため、`docs/adr/` に効力のない ADR が増える。ステータスと `docs/specifications.md` で見分ける
- 参考文献がない場合も「なし」と書く分、ADR が少し長くなる
