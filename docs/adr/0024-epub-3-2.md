# ADR 0024: EPUB の出力（ADR 0019）と CLI（ADR 0022）を一つにまとめ、出す版に EPUB 3.2 を加える

ステータス: 採択

## 文脈

この ADR は、ADR 0019 と ADR 0022 を置き換える。
EPUB 3.2 の本を作りたい。
しかし、ADR 0019 では、出す版を `2.0.1` と `3.0` に限り、EPUB 3.1 以降に固有の機能は扱わないとした。CLI の版の値（`--epub-version`）は ADR 0022 で決めている。
そこで、ADR 0019 と ADR 0022 の決定を一つに写し、出す版に `3.2` を加える。版の扱いに関わる箇所のほかは、決定の中身を変えない。

EPUB 3.1 と EPUB 3.2 について、次のことが分かっている。

- EPUB 3.1（IDPF、2017 年）は、パッケージ文書の `version` を `3.1` とした。版の番号を変えたことで、作る側、配る側、リーダーが二つの版の本を扱う必要が生じ、その負担が利点を上回ると判断された。EPUB 3.1 の商業出版の本は出回らなかったとされ、EPUBCheck も対応していない（手元で `version="3.1"` の EPUB を EPUBCheck 5.4.0 に掛けると OPF-001 の誤りになった）
- EPUB 3.2（W3C、2019 年）は、EPUB 3.0.1 のリーダーが 3.2 の本を読めることを目指し、3.1 の変更の一部を取り消した。パッケージ文書の `version` は `3.0` であり、EPUB 3.0 と 3.0.1 と同じである
- EPUB 3.2 では、NCX と OPF2 の `meta` 要素（`name` と `content` を持つもの）は、古い機能（legacy）とされた。EPUB 3 のリーダーは目次をナビゲーション文書から読み、NCX は EPUB 2 にしか対応しないリーダーのためにある
- EPUBCheck 5 は、`version` が `3.0` のパッケージを、最新の EPUB 3 の規則（EPUB 3.3）で検査する

EPUB 3.1 の出力も検討したが、取り消された版であり、EPUBCheck が検証できず、読めないリーダーがありうるため、加えないことにした。

利用者は EPUB の仕様に詳しいとは限らない。`3.2` を加えても出力が `3.0` とまったく同じなら、二つの版の違いが分からず、どちらを選べばよいか判断できない。そこで、`3.0` は古いリーダーのための NCX を含む版、`3.2` は EPUB 3.2 で古い機能とされた NCX を含まない版として、違いを持たせる。

### ADR 0019 の文脈

この ADR は、ADR 0003 と ADR 0014 を置き換える。
Kindle は、パッケージ文書の `<meta name="primary-writing-mode" content="…"/>` で本の組み方向（縦書きか横書きか）を読み取る。これがないと、縦書きの本が Kindle で意図どおりに扱われないことがある。
しかし、ADR 0003 では、特定のリーダーや配信サービスに固有の拡張（Kindle の独自のメタデータなど）は持たないとした。また、`book.toml` のキーは ADR 0014 で決めており、知らないキーは例外になる。
CLAUDE.md では、特定のリーダーに固有の拡張は ADR で決めてから入れるとしている。
そこで、ADR 0003 と ADR 0014 の決定を一つに写し、`primary-writing-mode` を加える。`primary-writing-mode` に関わる箇所のほかは、決定の中身を変えない。

`primary-writing-mode` は Kindle の拡張だが、ほかのリーダーは知らない `meta` を無視し、EPUBCheck も EPUB 2.0.1 と EPUB 3.0 のどちらでも誤りや警告にしない。そのため、入れても仕様への適合を損なわない。

#### ADR 0003 の文脈

EPUB の版によって、パッケージ文書（OPF）の書き方、目次の持ち方、本文の文書の形式が違う。

- EPUB 2.0.1：OPF 2.0.1 のパッケージ文書（`version="2.0"`）、目次は NCX（必須）、本文は XHTML 1.1
- EPUB 3.0：パッケージ文書は `version="3.0"`、目次はナビゲーション文書（必須）、本文は XHTML の構文で書いた HTML5、`dcterms:modified` が必須

一方、どちらの版も、zip の先頭に圧縮しない `mimetype` を置き、`META-INF/container.xml` からパッケージ文書を指す点は同じである。
epubize で作るのは日本語の縦書きの小説が主になる。

#### ADR 0014 の文脈

この ADR は、ADR 0013 を置き換える。
あとがき、付録、参考文献、索引などの後付けを扱いたい。後付けは、本文の後、奥付の前に置く付き物である。
しかし、ADR 0013 では、`meta/` に置けるのを表紙、扉、奥付に限り、ほかの付き物は本文として `body/` に置くとした。`body/` の文書はすべて章（`bodymatter chapter`）になるため、後付けを landmarks や guide で示せない。
そこで、ADR 0013 の決定の全体をこの ADR に写し、後付けを `meta/` に決まった名前で置けるようにする。後付けに関わる箇所のほかは、決定の中身を変えない。

ADR 0013 は、ADR 0009 と ADR 0012 を一つに写して扉を加えたものである。扉（標題紙、titlepage）は、表紙の次に置き、題名、著者、出版者などを組む付き物である。ADR 0009 では表紙と奥付以外の付き物を `meta/` に置かないとし、ADR 0012 では landmarks と guide に `titlepage` の項目を書かないとしていた。

##### ADR 0009 の文脈

各決定に至った経緯は次のとおり。

- EPUB 2.0.1（OPS 2.0.1）の本文では、XHTML 1.1 のルビのモジュールも MathML も使えず、EPUBCheck で誤り（RSC-005）になる（ADR 0006、ADR 0007）
- EPUBCheck は、ファイル名に空白類（ASCII の空白、全角空白、ノーブレークスペース、タブなど）を含むと警告（PKG-010）を出し、タブは誤り（PKG-009）にもなる（ADR 0007）
- MathML や `ruby` 要素を使う原稿を、EPUB 2.0.1 を作るためだけに拒むのは使いにくい。使う側は同じ原稿を両方の版に使いたい（ADR 0007）
- 一つの章の中に節や項を立てる原稿では、章の中の構成が目次に出ない。節ごとにファイルを分けるのは書きにくい（ADR 0008）

ADR 0004 では、本を表す値（`book`）を受け取る関数を公開 API とした。
プログラムから使う側（epubize など）はこれで足りるが、手で原稿を書く人には、値を組み立てるコードを書く手間がかかる。
ファイルを決まった形に並べたディレクトリを渡せば `book` が得られるようにしたい。

置き方を決めるにあたっては、次を重く見る。

- 原稿を書く人が、設定を書かなくても、ファイルの名前だけで並びを決められること
- 並びや目次の決め方が、ファイルの一覧を見れば予想できること（驚き最小）
- 誤りや曖昧さを黙って解決せず、例外で知らせること

本文は Markdown で書けると手早いが、細かく組みたい箇所は XHTML や HTML で直接書きたい。
小説では、ルビと脚注を Markdown の中で書けることが要る。CommonMark にはどちらの記法もない。
EPUB の本文は XHTML でなければならないため、Markdown と HTML は XHTML に直す必要がある。

##### ADR 0012 の文脈

ADR 0010 では、EPUB 3 の `landmarks` を作らないとした。
しかし、文書の役割（表紙、本文、後付け）を `epub:type` で付けるようになったため、それをもとに、リーダーが表紙や本文の始まりへ移れる `landmarks` を作れる（ADR 0011）。

ADR 0009 では、ディレクトリの構造（部、章）と文書の中の見出し（節）から目次を作るとした。
しかし、本文の文書そのものには、どれが部の扉で、どれが章で、どこからどこまでが節かという構造が書かれていない。
EPUB 3.0 では、構造の意味を `epub:type`（EPUB 3 Structural Semantics Vocabulary）で示せ、HTML の `section` 要素で節のまとまりを表せる。
リーダーや支援技術は、これを使って文書の役割を読み取れる。

EPUB 2.0.1（OPS 2.0.1）の本文には `epub:type` も `section` 要素もない。

### ADR 0022 の文脈

この ADR は ADR 0018 を置き換える。
ADR 0018 では、引数の解析に `@std/cli` の `parseArgs` を使うとした。
その後、作者の全リポジトリに共通する方針（グローバルの CLAUDE.md）で、ライセンスに問題がなく再実装が容易な依存は、依存に入れずに再実装すると定められた。必要な機能が限られる場合は、必要な機能だけを実装してよい。
この CLI が使う `parseArgs` の機能は、文字列と真偽のオプション、短い別名、`--name=value` の形、位置引数、知らないオプションの検出に限られ、再実装は容易である。`@std/cli` のライセンスは MIT である。
そこで、引数の解析を自前で書くことに改め、決定の全体をこの ADR に写す。引数の解析の方法のほかは、ADR 0018 の決定の中身を変えない。

ADR 0018 は、ADR 0017 を置き換えたものである。
ADR 0017 では、`build` の版の既定を両方（`all`）とし、`check` と `toc` の既定は `3.0` のままとした。
しかし、コマンドによって既定の版が違うと、`check` を通した本を `build` すると、調べていない EPUB 2.0.1 も作られる。
そこで、`check` と `toc` の既定も両方の版にそろえ、`toc` でも両方の版を扱えるようにして、決定の全体を ADR 0018 に写した。

ADR 0017 は、ADR 0016 を置き換えて、`build` の版の既定を `3.0` から両方に改めたものである。`build` は EPUB 2.0.1 にしか対応しないリーダーのためにも使うため、何も指定しないときは両方の版を作る方が使いやすい。

ADR 0016 は、ADR 0015 を置き換えて、インストールのコマンドに `--config deno.json` を加えたものである。`deno install -g` は、`--config` を付けないと `deno.json` を読まず、`imports` に書いた依存を解決できなかった。

ADR 0014 では、決まった形に並べたディレクトリから本を読む `loadBook` を定めた。
しかし、使うには TypeScript のコードを書いて `loadBook` と `buildEpub` を呼ぶ必要がある。
原稿を書く人が、コードを書かずに、端末からディレクトリを EPUB にできるようにしたい。
EPUB を作る前に誤りや警告だけを確かめたい、目次がどうなるかを見たい、新しい本の雛形を作りたい、という用途もある。

## 実装すること

### EPUB の出力と、ディレクトリから本を読む（ADR 0019 から）

#### EPUB の出力（ADR 0003 から）

- 呼び出し側は、一つの入力（書誌情報、本文、スタイルシート、画像）と、出す版（`"2.0.1"`、`"3.0"`、`"3.2"` のいずれか。`"3.2"` は後述）を渡す
- どちらの版でも、次を作る
  - zip の最初の項目として、圧縮しない `mimetype`（内容は `application/epub+zip`、余分な項目を付けない）
  - `META-INF/container.xml`
  - パッケージ文書、本文の文書、スタイルシート、画像を、決まったディレクトリ（`OEBPS/`）の下に置く
  - 本文の文書は、呼び出し側が渡した XHTML の本文（`body` の中身）を、版に合った文書の形で包んで作る
- EPUB 2.0.1 では、次を作る
  - OPF 2.0.1 のパッケージ文書。`dc:identifier`、`dc:title`、`dc:language` を必ず書く
  - NCX（`toc.ncx`）の目次。spine の `toc` 属性から指す
  - 本文は XHTML 1.1 の DOCTYPE を持つ文書とする
  - 表紙の画像は `<meta name="cover" content="…">` で示す
- EPUB 3.0 では、次を作る
  - `version="3.0"` のパッケージ文書。`dc:identifier`、`dc:title`、`dc:language`、`dcterms:modified` を必ず書く
  - ナビゲーション文書（`nav.xhtml`、`properties="nav"`）の目次
  - EPUB 2 にしか対応しないリーダーのため、NCX も作り、spine の `toc` 属性から指す
  - 本文は XHTML の構文で書いた HTML5 の文書とする
  - 表紙の画像は `properties="cover-image"` で示す
  - 頁送りの向き（`page-progression-direction`、`ltr` か `rtl`）を spine に書けるようにする。縦書きの本では `rtl` にする
- 目次は入れ子にできるようにする（章の下に話を並べる、など）
- 画像は、どちらの版でも中核の形式（JPEG、PNG、GIF、SVG）を扱う
- 書誌情報の文字列は、XML として正しくなるように実体参照に直して書く

#### ディレクトリから本を読む（ADR 0014 から）

##### ディレクトリの構成

```
<project>/
  book.toml          書誌情報
  body/              本文
    01-prologue.md
    02-part1/
      index.md       部の扉（任意）
      01-first.md
      02-second.xhtml
      03-third.html
    03-epilogue.md
  meta/              表紙、扉、後付け、奥付
    cover.md
    titlepage.md
    afterword.md
    colophon.xhtml
  assets/            スタイルシートと画像
    style.css
    images/
      cover.jpg
```

- ディレクトリを読んで `book`（ADR 0004）を返す関数 `loadBook(dir, options)` を公開する。EPUB を作るのは従来どおり `buildEpub(book, options)` とする
  - `options.version` に、`buildEpub` と同じく `"2.0.1"`、`"3.0"`、`"3.2"` のいずれかを渡す。ルビと脚注の書き出し方が版で違うため、`loadBook` の時点で版を決める。`loadBook` と `buildEpub` に違う版を渡した場合の結果は保証しない
  - `options.onWarning` に関数を渡すと、警告をその関数で受け取る。渡さなければ、`console.warn` で標準エラー出力に書く。警告では処理を止めない
- `loadBook` は、`buildEpub` を含む中核のモジュールとは別のモジュールに置く。中核のモジュールは、ADR 0004 のとおり外部の依存を持たない
- 名前が `.` で始まるファイルとディレクトリ（`.DS_Store` など）は、どこにあっても無視する
- ファイルとディレクトリの名前は NFC に正規化して扱う

##### 書誌情報（`book.toml`）

- 書誌情報は `<project>/book.toml` に TOML で書く。ファイルがなければ例外とする
- キーは ADR 0004 の書誌情報に対応させ、次のとおりとする

  ```toml
  identifier = "urn:uuid:00000000-0000-0000-0000-000000000000"
  title = "題名"
  language = "ja"
  authors = ["著者"]
  publisher = "出版者"
  description = "説明"
  modified = 2026-10-09T00:00:00Z
  page_progression_direction = "rtl"
  primary_writing_mode = "vertical-rl"
  cover_image = "assets/images/cover.jpg"
  ```

- `identifier`、`title`、`language` は必須とする。ほかは省略してよい
- 値の型は、`authors` を文字列の配列、`modified` を TOML のオフセット付きの日時、`page_progression_direction` を `"ltr"` か `"rtl"`、`primary_writing_mode` を `"horizontal-lr"`、`"horizontal-rl"`、`"vertical-lr"`、`"vertical-rl"` のいずれか（後述）、ほかを文字列とする。型が違えば例外とする
  - `modified` はタイムゾーンのない日時（ローカル日時）を例外とする。`dcterms:modified` は UTC で書くため、どの時点かが決まらない値は受け取らない。省略した場合の扱いは ADR 0004 に従う
- `cover_image` は、プロジェクトのディレクトリからの相対パスで、`assets/` の下の画像を指す。なければ、または画像でなければ例外とする
- 知らないキーは例外とする。綴りの誤りを黙って無視しないため

##### TOML の解析

- TOML の解析器は自前で書く。外部の依存は持たない
- TOML 1.0.0 の全体に対応する。書誌情報に使うのは一部のキーだが、正しい TOML を受け付けないことは驚きになるため、構文は仕様のとおりに受け付け、誤った TOML は位置を示す例外とする

##### 本文（`body/`）

- 本文は `body/` の下に、Markdown（`.md`）、XHTML（`.xhtml`）、HTML（`.html`）のいずれかで書く。一つの本の中で混ぜてよい
- どの形式でも、ファイルには `body` の中身（断片）を書く。版に合った文書の形で包むのは `buildEpub` が行う（ADR 0003）
- 拡張子を除いた名前が同じファイルが同じディレクトリに二つ以上あれば、例外とする（`01-intro.md` と `01-intro.xhtml` など）。どれを使うべきか決められないため
- `.md`、`.xhtml`、`.html` 以外の拡張子のファイルが `body/` の下にあれば、例外とする。拡張子の大文字と小文字は区別し、`.MD`、`.markdown`、`.htm` も例外とする
- `body/` がない、または本文のファイルが一つもなければ、例外とする。中身のないサブディレクトリも例外とする

##### 本文の形式ごとの変換

三つの形式は、いずれも一度 HTML の構文木（hast）に読み、同じ処理（参照の書き換え、題名と節の取り出し）を経て、自前の書き出し器で XHTML の構文に書き出す。
ルビと脚注の記法は Markdown だけのものとし、XHTML と HTML では要素を直接書く。

- Markdown（`.md`）
  - CommonMark として解釈する。これに、後に定めるルビと脚注の記法を加える
  - unified 系のライブラリ（`remark-parse`、`remark-rehype`、`rehype-raw`）で hast にする
  - Markdown の中の生の HTML は、HTML Living Standard の構文として解析し、`.html` と同じ規則で変換する
- XHTML（`.xhtml`）
  - XML として解析する。整形式でなければ、位置を示す例外とする。HTML として読み直すことはしない。HTML で書くなら拡張子を `.html` にする
  - XML の解析器は自前で書く。対象は断片に要るものに限る（要素、属性、文字、コメント、CDATA 区間、事前定義の 5 つの実体参照と文字参照）。DOCTYPE と、事前定義のもの以外の実体参照は例外とする
  - 断片は、`buildEpub` が包む文書と同じ名前空間の宣言（既定の名前空間が XHTML、`epub:` の接頭辞など）の中にあるものとして解析する。`epub:type` などを、断片の中で宣言せずに書けるようにするため
- HTML（`.html`）
  - HTML Living Standard の断片の解析（文脈は `body`）で読む。unified 系のライブラリ（`rehype-parse`）を使う
  - 解析の誤りからの回復は、HTML Living Standard の規則に従う。閉じ忘れた要素、属性の引用符の省略、`<br>` のような空要素などは、そのまま XHTML に直す
  - 名前付きの文字参照（`&nbsp;` など）は文字に直す
  - `epub:type` のような接頭辞の付いた属性は、`buildEpub` が宣言する接頭辞であれば、その名前空間の属性に直す
- 次の場合は XHTML に直せないものとして、ファイルと位置を示す例外とする。Markdown の中の生の HTML にも当てはめる
  - 要素や属性の名前が XML の名前として正しくない、または知らない接頭辞を持つ
  - 名前空間に直した後で、同じ要素に同じ属性が重なる
  - XML 1.0 で使えない文字（U+0000 から U+0008 などの制御文字）がある
  - コメントの中身に `--` を含む、または `-` で終わる
  - 断片の中に `<!DOCTYPE>`、`html`、`head`、`body` がある（断片の解析では黙って捨てられ、`head` の中身が失われるため）
- XHTML への書き出し器は自前で書く。空要素の閉じ方、名前空間の宣言、文字の実体参照への直し方を、EPUB に合わせて制御するため

##### ルビ（Markdown）

Web 小説の投稿サイトや青空文庫で広く使われている書き方に合わせる。

- `｜親文字《ルビ》` と書く。`｜`（U+FF5C）の代わりに `|`（U+007C）でもよい
- 親文字が漢字だけのときは、`｜` を省いて `漢字《かんじ》` と書ける。このとき親文字は、`《` の直前から前に続く漢字の並びとする
  - 漢字は、Unicode の `Script=Han` の文字と、`々`、`〆`、`〇`、`ヶ` とする
- 次の場合はルビとせず、書いたとおりの文字として出す
  - 親文字かルビが空のとき（`｜《ルビ》`、`漢字《》`）
  - `｜` の後に `《…》` が続かないとき（文中で `|` を文字として書いた場合を含む）
  - ルビの中に `《` か `｜` を含むとき
- `《` を文字として書きたいときは `\《` と書く
- 記法は、一つの文字列のノード（mdast の `text`）の中だけで解釈する。強調やリンクをまたぐ親文字は書けない。コードスパンとコードブロックの中は解釈しない
- 親文字の全体に、ルビの全体を付ける（グループルビ）。一文字ずつ対応させるモノルビは扱わない
- 書き出し方は次のとおりとする
  - EPUB 3.0：`<ruby>漢字<rp>（</rp><rt>かんじ</rt><rp>）</rp></ruby>`。`rp` は、ルビに対応しないリーダーで `漢字（かんじ）` と表示するため
  - EPUB 2.0.1：`<span class="ruby"><span class="rb">漢字</span><span class="rp">（</span><span class="rt">かんじ</span><span class="rp">）</span></span>`。OPS 2.0.1 では `ruby` 要素を書けないため、ルビに対応しないリーダーと同じ `漢字（かんじ）` の表示にする。クラスを付け、スタイルシートで括弧を隠したり、ルビを小さく組んだりできるようにする
- 解釈は、Markdown を mdast にした後に `text` のノードを書き換える処理として自前で書く

##### EPUB 2.0.1 で使えない要素の警告

- `loadBook` に `version: "2.0.1"` を渡したとき、変換した本文に次の要素があれば、例外にせず、要素ごとに警告を出す
  - MathML の `math` 要素
  - `ruby` 要素（XHTML や HTML に直接書いたもの、Markdown の中の生の HTML に書いたもの）
- Markdown のルビの記法は、EPUB 2.0.1 では括弧書きの `span` で出すため、警告の対象にならない
- 要素は書き換えずにそのまま出す。作った EPUB は EPUBCheck で誤りになる

##### 脚注（Markdown）

- GFM の脚注の記法で書く。本文に `[^ラベル]` と書いて参照し、`[^ラベル]: 本文` で定義する
  - 解析には `micromark-extension-gfm-footnote` と `mdast-util-gfm-footnote` を使う。GFM のほかの記法（表、取り消し線など）は加えない
- 脚注は文書ごとに扱う。定義は同じ文書の中の参照からだけ使え、注の本文は、その文書の末尾に、最初に参照した順に置く
- 番号は文書ごとに 1 から付け、参照の箇所と注の本文の両方に表示する。ラベルの文字列は表示しない
- 次の場合は例外とする。GFM では黙って文字のまま出すか捨てるが、書き損じを見落とさないため
  - 定義のない参照
  - 参照されない定義
  - 同じラベルの定義が二つ以上ある
- 一つの注を二度以上参照してよい。注の本文からの戻りのリンクは、最初の参照を指す
- ID は、注の本文を `fn-<番号>`、参照を `fnref-<番号>`（二度目以降は `fnref-<番号>-<回数>`）とする。同じ文書の中に、ユーザーが書いた同じ ID があれば例外とする
- 書き出し方は次のとおりとする。CSS で整えられるよう、どちらの版でも `noteref`、`footnotes`、`footnote` のクラスを付ける
  - EPUB 3.0
    - 参照：`<sup><a class="noteref" id="fnref-1" href="#fn-1" epub:type="noteref">1</a></sup>`
    - 注の本文：`<aside class="footnote" id="fn-1" epub:type="footnote"><p><a href="#fnref-1">1</a> 注の本文</p></aside>` を、文書の末尾の `<div class="footnotes">` の中に並べる。リーダーが注をポップアップで出せるようにするため
  - EPUB 2.0.1
    - 参照：`<sup><a class="noteref" id="fnref-1" href="#fn-1">1</a></sup>`
    - 注の本文：`<div class="footnote" id="fn-1"><p><a href="#fnref-1">1</a> 注の本文</p></div>` を、文書の末尾の `<div class="footnotes">` の中に並べる。XHTML 1.1 には `aside` も `epub:type` もないため
  - 注の本文が複数の段落からなるときは、番号のリンクを最初の段落の先頭に置く
- mdast から hast への変換は、`remark-rehype` の既定の脚注の出力（GFM の `section`）を使わず、上の形を作る処理を自前で書く
- 注の本文の中でも、ルビ、強調、リンクなどは本文と同じく書ける。注の本文の中の脚注の参照は例外とする

##### ライブラリへの依存の方針

- Markdown と HTML の解析には unified 系のライブラリを使い、`deno.json` の `imports` で版を固定する
- 使う部分が小さく、自前で書いても仕様が小さくまとまり、テストで同じ結果になることを確かめられるものは、再実装して依存を減らす。この ADR の時点では、XHTML への書き出し（`hast-util-to-html` などの代わり）を自前で書く
- CommonMark の解析と HTML Living Standard の解析は小さくないため、再実装しない

##### 並び

- 同じディレクトリの中の項目（ファイルとサブディレクトリ）は、名前の文字コード順に並べる
  - NFC に正規化した名前を、Unicode の符号位置で比べる。ロケールに依存する比較や、数字を数として比べる比較（自然順）はしない
  - JavaScript の文字列の比較（UTF-16 の符号単位の比較）は、サロゲートペアで符号位置の順と食い違うため使わない
- 並びを明示したい場合は、ユーザーが名前の先頭に連番を付ける（`01-`、`02-` など）。桁は揃えるものとする（`10-` は `2-` より前に来る）
- サブディレクトリは、その位置で中身を展開する（深さ優先）。サブディレクトリの中に `index`（`.md`、`.xhtml`、`.html` のいずれか）があれば、それを中の最初の文書とする
- 本全体の読み順（spine）は、`meta/cover`、`meta/titlepage`、`body/` の文書、`meta/` の後付け（後に定める順）、`meta/colophon` の順とする

##### 表紙、扉、後付け、奥付（`meta/`）

- `meta/` には、表紙の文書 `cover`、扉の文書 `titlepage`、奥付の文書 `colophon` を、本文と同じ三つの形式のいずれかで置ける。どれも任意とし、`meta/` 自体がなくてもよい
- 扉は、ユーザーが書いた文書だけを使う。書誌情報から扉を自動で作ることはしない
- `meta/` には、次の後付けの文書も、同じ三つの形式のいずれかで置ける。どれも任意とする。読み順は、本文の後、奥付の前で、表の順とする

| 名前              | 後付け     |
| ----------------- | ---------- |
| `afterword`       | あとがき   |
| `acknowledgments` | 謝辞       |
| `appendix`        | 付録       |
| `bibliography`    | 参考文献   |
| `glossary`        | 用語集     |
| `index`           | 索引       |
| `copyright-page`  | 著作権表示 |

- `meta/` の `index` は索引であり、`body/` のディレクトリの `index`（部の扉）とは別の意味である
- 後付けは、奥付と同じく目次に入れる。目次では、本文の項目の後、奥付の項目の前に、読み順に並べる。題名は本文と同じ規則で決める（見出しがなければファイルの名前、たとえば `afterword`）。後付けの見出しは節にする
- 後付けの文書は一つの種類につき一つとし、サブディレクトリは作れない
- `meta/` に、`cover`、`titlepage`、上の後付け、`colophon` のほかの名前のファイル、サブディレクトリ、拡張子を除いて同じ名前のファイルの組があれば、例外とする

##### スタイルシートと画像（`assets/`）

- スタイルシートと画像は `assets/` の下に置く。サブディレクトリを作ってよい。`assets/` 自体がなくてもよい
- 扱う拡張子とメディアタイプは次に限る。ほかの拡張子は例外とする。大文字と小文字は区別する（`.JPG` は例外）
  - `.css`：`text/css`
  - `.jpg`、`.jpeg`：`image/jpeg`
  - `.png`：`image/png`
  - `.gif`：`image/gif`
  - `.svg`：`image/svg+xml`
- `assets/` の下のファイルは、本文から参照されていなくても、すべて EPUB に入れる
- `assets/` の下のファイルは、プロジェクトのディレクトリからの相対パス（`assets/images/cover.jpg` など）を `book` のパスとする。ディレクトリの構成を保つため、スタイルシートの中の `url()` の相対パスは書き換えずにそのまま使える
- ただし、ファイルとディレクトリの名前に含まれる空白類は、一文字ずつ `_` に置き換えた名前で `book` のパスとする
  - 空白類は、JavaScript の正規表現の `\s` に合う文字とする（ASCII の空白とタブ、改行、U+00A0、U+3000 など）
  - 置き換えはパスの区切りごとに行う。ディレクトリの名前も置き換える
  - 本文の中の参照と `book.toml` の `cover_image` は、元のファイルの名前（空白を含む名前）で書く。`loadBook` は、置き換えた後のパスに書き換える
  - 置き換えた結果、二つ以上のファイルが同じパスになる場合（`a b.png` と `a_b.png` など）は、例外とする
  - 名前を置き換えたファイルごとに、警告を出す。スタイルシートの中の `url()` は書き換えないため、空白を含む名前を `url()` で指していると、参照が切れることを知らせる
  - 本文と `meta/` のファイルの名前は、EPUB の中では読み順の番号になるため、置き換えの対象にしない
  - `buildEpub` に渡す `book` のパスは、置き換えない。プログラムから `book` を組み立てる側は、本文の中の参照と合わせてパスを決めているためである
- スタイルシートは、すべての `.css` を、すべての内容文書（表紙、扉、本文、後付け、奥付）に適用する。順は、パスの文字コード順（並びの規則と同じ比べ方）とする

##### 文書の置き場所と参照の書き換え

- `buildEpub` は、内容文書を `OEBPS/text/` の下に、読み順の番号を 4 桁以上にゼロ詰めした名前（`0001.xhtml`、`0002.xhtml` …）で置く。スタイルシートと画像は `OEBPS/` の下に `book` のパスのまま置く。ADR 0004 で「ライブラリが決める」とした名前を、この規則に定める
- `loadBook` は、文書の中の次の参照を、元のファイルの位置からの相対パスとして解決し、EPUB の中での位置からの相対パスに書き換える
  - `img` の `src`、SVG の `image` の `href` と `xlink:href`：`assets/` の下の画像を指すこと
  - `a` の `href`：`assets/` の下のファイル、または `body/` か `meta/` の文書を指すこと。文書へのリンクは、元のファイルの名前（`02-second.md` など）で書き、断片識別子（`#…`）は保つ
- 参照の書き方の規則
  - パスはパーセントエンコードを解いてから解決し、書き換えた後はエンコードして書く
  - `#` だけの参照は書き換えない
  - `a` の `href` で、スキームを持つもの（`https:`、`mailto:` など）は書き換えない
  - `img` と SVG の `image` で、スキームを持つもの（外部の画像）は例外とする
  - `/` で始まる参照、プロジェクトの外や上で定めた範囲の外を指す参照、指す先のファイルがない参照は例外とする
  - 断片識別子が指す先が文書の中にあるかは確かめない

##### 目次

目次は、設定を書かずに、ディレクトリの構成と文書の中の見出しから作る。
ディレクトリの構造（部、章）を目次の上の段とし、その下に、各文書の中の見出しを節として入れ子で続ける。

- `body/` の文書は、一つのファイルを目次の一つの項目とする
- サブディレクトリは、子を持つ項目とする。子はディレクトリの中身を、並びの規則どおりに並べたものとする
  - `index` の文書があれば、その文書を項目の行き先とし、子には含めない
  - なければ、ディレクトリの中の最初の文書を項目の行き先とする。NCX の `navPoint` は行き先を必須とするため、ナビゲーション文書でも同じ行き先にそろえる
- 項目の題名は、次の順で決める
  1. 文書の最初の見出し（`h1` から `h6`。レベルは問わない。Markdown の ATX と Setext の見出しを含む）の文字列。タグは除き、文字だけを使う。`rt` と `rp` の中身と、脚注の参照は除き、ルビは親文字だけを残す（NCX の目次は文字しか持てないため、ナビゲーション文書もそろえる）
  2. 見出しがなければ、ファイルの名前から拡張子と先頭の連番を除いたもの
- ディレクトリの項目の題名は、`index` の文書があれば 1. と 2. で決め、なければディレクトリの名前から先頭の連番を除いたものとする
- 先頭の連番は、正規表現 `^[0-9]+[-_.]` に合う部分とする。除いた残りが空になる場合（`01.md` など）は除かない
- 表紙と扉は目次に入れない。後付けは本文の項目の後に、奥付は目次の最後の項目とし、題名は本文と同じ規則で決める

##### 節（文書の中の見出し）

- 各文書の項目の下に、その文書の中の見出しを、節として入れ子で続ける
  - 対象は、文書の題名に使った見出し（文書の最初の見出し）を除く、すべての `h1` から `h6` とする
  - 見出しの入れ子は、レベルで決める。ある見出しは、それより前にある、レベルの数がより小さい見出しのうち最も近いものの子とする。そのような見出しがなければ、文書の項目の直下に置く
  - レベルが飛んでもよい（`h2` の次に `h4` があれば、`h4` は `h2` の子とする）
- ディレクトリの `index` の文書の節は、そのディレクトリの項目の下に、子の項目より前に置く。読み順と目次の順をそろえるためである
- 後付けと奥付の節も、それぞれの項目の下に置く。表紙と扉は目次に入れないため、表紙と扉の見出しは節にせず、`id` も付けない
- 脚注の欄（`<div class="footnotes">`）の中の見出しは、節にも題名にもしない
- 節の題名は、文書の題名と同じ規則で決める。HTML の空白（ASCII の空白類）の並びは一つの空白にまとめ、前後の空白を除く。全角空白などは残す。空になる見出しは節にしない
- 見出しに `id` があれば、それを節の行き先に使う。なければ、文書ごとに `sec-1`、`sec-2` … を文書の中の順に付け、本文の見出しの要素に書き出す。本文に同じ `id` がすでにあれば、その番号を飛ばして次の番号を使う
- 本を表す値の章（`Chapter`）に、その章の文書の中の節の並び `sections` を持たせる。節（`Section`）は、題名、本文の中の見出しの `id`、子の節を持つ
- `buildEpub` は、章の項目の子として、まず `sections` を、次に `children`（子の章）を、この順で目次に書く。節の行き先は `<章の文書>#<id>` とし、`id` はパーセントエンコードして書く
- `buildEpub` は、`sections` を持つ章が本文を持つこと、節の題名が空白だけでないこと、`id` が空でなく空白類と `#` を含まないこと、本文の中にその `id` を持つ要素があることを調べ、満たさなければ例外とする
- NCX の `playOrder` は、行き先（断片識別子を含む）ごとに、目次に現れる順に振る

##### 警告の受け取り方

- 警告は、種類を表す `code`、ファイルのパス、分かる場合は行と列、メッセージを持つ
  - `renamed-file`：`assets/` のファイル名の空白を置き換えた
  - `mathml-in-epub-2`：EPUB 2.0.1 の本文に MathML がある
  - `ruby-in-epub-2`：EPUB 2.0.1 の本文に `ruby` 要素がある
- 警告を誤りとして扱いたい場合は、使う側が `onWarning` の中で例外を投げる

##### 部・章・節の意味づけ、landmarks、guide

###### 本を表す値

- 本を表す値に、扉の文書 `titlepage` を、表紙の文書（`cover`）と同じ形で持てるようにする。`buildEpub` は、扉を表紙の次（表紙がなければ最初）の読み順に置き、目次には入れない。内容文書の `title` は本の題名とする
- 章（`Chapter`）、表紙の文書（`cover`）、扉の文書（`titlepage`）に、文書の役割を表す `epubType` を持てるようにする。値は、空白で区切った `epub:type` の語の並びとする
- `buildEpub` は、EPUB 3.0 では、`epubType` を内容文書の `body` 要素の `epub:type` 属性に書く。EPUB 2.0.1 では属性を書かず、`guide` を作るためにだけ使う
- `buildEpub` は、`epubType` が空白だけでないこと、XML で使えない文字を含まないことを調べ、満たさなければ例外とする。語が語彙にあるかは調べない

###### loadBook が付ける役割

`loadBook` は、渡した版に関わらず、次の `epubType` を付ける。

| 文書                                             | `epubType`                                         |
| ------------------------------------------------ | -------------------------------------------------- |
| 表紙（`meta/cover`）                             | `frontmatter cover`                                |
| 扉（`meta/titlepage`）                           | `frontmatter titlepage`                            |
| `body/` の直下のディレクトリの `index`（部の扉） | `bodymatter part`                                  |
| それより深いディレクトリの `index`               | `bodymatter division`                              |
| `body/` のほかの文書                             | `bodymatter chapter`                               |
| 後付け（`meta/afterword` など）                  | `backmatter <名前>`（`backmatter afterword` など） |
| 奥付（`meta/colophon`）                          | `backmatter colophon`                              |

EPUB 2.0.1 では、`buildEpub` が `epubType` を本文に書かないため、本文は変わらない。`guide` にだけ使う。

###### 節の section 要素

- `loadBook` に `version: "3.0"` を渡したとき、本文の直下（ほかの要素の中でない位置）にある見出しのうち、ADR 0009 で節にしたものごとに、その見出しから始まるまとまりを `section` 要素で囲む
  - まとまりは、その見出しから、同じかより小さいレベルの数の、次の節の見出しの前までとする
  - 入れ子は見出しのレベルで決める。`h2` の節の中に `h3` の節を入れる
  - 文書の題名に使った見出しと、それより前の内容は、`section` で囲まない
  - 脚注の欄（`<div class="footnotes">`）の前で、開いている `section` をすべて閉じる
- 節の `id` は、ADR 0009 のとおり見出しの要素に置き、`section` 要素には付けない。目次の行き先は変わらない
- ほかの要素の中にある見出し（`div` や `blockquote` の中など）は、目次の節にはなる（ADR 0009）が、`section` で囲まない。まとまりの範囲が要素の境界をまたぐためである
- `section` 要素に `epub:type` は付けない
- `version: "2.0.1"` では囲まない

###### landmarks

- `buildEpub` は、EPUB 3.0 では、ナビゲーション文書に、目次の `nav` の後に `<nav epub:type="landmarks" hidden="">` を書く。EPUB 2.0.1 では書かない
- 項目は次の順とし、行き先がある項目だけを書く

| 項目の `epub:type`                                                                                            | 行き先                                                                                                                      |
| ------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `cover`                                                                                                       | 表紙の文書（`book.cover`）                                                                                                  |
| `titlepage`                                                                                                   | 扉の文書（`book.titlepage`）                                                                                                |
| `bodymatter`                                                                                                  | `epubType` に `bodymatter` を含む最初の章の文書。そのような章がなければ、最初の章の文書（表紙と扉を除く読み順の最初の文書） |
| `backmatter`                                                                                                  | `epubType` に `backmatter` を含む最初の章の文書                                                                             |
| `afterword`、`acknowledgments`、`appendix`、`bibliography`、`glossary`、`index`、`copyright-page`、`colophon` | `epubType` にその語を含む最初の章の文書。この順で書く                                                                       |

- 項目の表示名は、書誌情報の言語で決める。言語が `ja` か `ja-` で始まるときは日本語、それ以外は英語とする

| 項目              | 日本語     | 英語             |
| ----------------- | ---------- | ---------------- |
| `cover`           | 表紙       | Cover            |
| `titlepage`       | 扉         | Title Page       |
| `bodymatter`      | 本文       | Start of Content |
| `backmatter`      | 後付け     | Back Matter      |
| `afterword`       | あとがき   | Afterword        |
| `acknowledgments` | 謝辞       | Acknowledgments  |
| `appendix`        | 付録       | Appendix         |
| `bibliography`    | 参考文献   | Bibliography     |
| `glossary`        | 用語集     | Glossary         |
| `index`           | 索引       | Index            |
| `copyright-page`  | 著作権表示 | Copyright        |
| `colophon`        | 奥付       | Colophon         |

- `hidden` を付け、リーダーが本文として表示しないようにする
- 目次（`toc`）の項目は書かない。ナビゲーション文書は読み順（spine）に入れない（ADR 0009）ため、landmarks から指すと EPUBCheck で誤り（RSC-011）になる
- `loadBook` の役割（`epubType`）は上の表のとおりなので、`loadBook` で読んだ本では、表紙、扉、本文の最初の文書、後付けの最初の文書（`backmatter`）、後付けのそれぞれ、奥付が landmarks に入る

###### guide

- `buildEpub` は、EPUB 2.0.1 では、パッケージ文書の `spine` の後に `<guide>` を書く。EPUB 3.0 では書かない
- 項目は次の順とし、行き先がある項目だけを書く

| `reference` の `type` | 行き先                                               |
| --------------------- | ---------------------------------------------------- |
| `cover`               | 表紙の文書（`book.cover`）                           |
| `title-page`          | 扉の文書（`book.titlepage`）                         |
| `text`                | landmarks の `bodymatter` と同じ文書                 |
| `other.afterword`     | `epubType` に `afterword` を含む最初の章の文書       |
| `acknowledgements`    | `epubType` に `acknowledgments` を含む最初の章の文書 |
| `other.appendix`      | `epubType` に `appendix` を含む最初の章の文書        |
| `bibliography`        | `epubType` に `bibliography` を含む最初の章の文書    |
| `glossary`            | `epubType` に `glossary` を含む最初の章の文書        |
| `index`               | `epubType` に `index` を含む最初の章の文書           |
| `copyright-page`      | `epubType` に `copyright-page` を含む最初の章の文書  |
| `colophon`            | `epubType` に `colophon` を含む最初の章の文書        |

- `title` は、landmarks の同じ項目の表示名とする（`text` は `bodymatter` の、`acknowledgements` は `acknowledgments` の表示名）
- OPF 2.0.1 の `guide` の型にない後付け（あとがき、付録）は、仕様にしたがって `other.` を付けた型にする。謝辞の型は OPF 2.0.1 の綴り（`acknowledgements`）とする
- 目次（`toc`）の項目は書かない。OPF 2.0.1 の `guide` は XHTML の文書を指すものだが、EPUB 2.0.1 では目次を NCX だけで持ち、目次の XHTML の文書がないためである
- `loadBook` で読んだ本では、表紙、扉、本文の最初の文書、後付けのそれぞれ、奥付が `guide` に入る

#### Kindle の primary-writing-mode

- 本を表す値の書誌情報に、本の組み方向を表す `primaryWritingMode` を持てるようにする。値は `horizontal-lr`、`horizontal-rl`、`vertical-lr`、`vertical-rl` のいずれかとする
- `buildEpub` は、どちらの版でも、`primaryWritingMode` があればパッケージ文書の `metadata` に `<meta name="primary-writing-mode" content="…"/>` を書く。ないときは書かない
- `buildEpub` は、`primaryWritingMode` が上の四つのどれでもないとき、`pageProgressionDirection` と食い違うとき（`vertical-rl` と `horizontal-rl` は `rtl`、`vertical-lr` と `horizontal-lr` は `ltr` と合う）、例外とする
- `book.toml` に、キー `primary_writing_mode` を加える。値は上の四つのいずれかの文字列とする。ほかの値は例外とする
- `loadBook` は、`primary_writing_mode` を書誌情報の `primaryWritingMode` にする。書いていないときは、`page_progression_direction` から決める。`rtl` なら `vertical-rl`、`ltr` なら `horizontal-lr` とする。どちらも書いていなければ、`primaryWritingMode` を持たない
  - 右から左の横書き（`horizontal-rl`）の本は、`primary_writing_mode` を書いて指定する
- `primary_writing_mode` と `page_progression_direction` を両方書いて食い違うときは、例外とする
- `primary_writing_mode` から `page_progression_direction` を決めることはしない。頁送りの向きは、ADR 0003 のとおり `page_progression_direction` で指定する

### CLI（ADR 0022 から）

#### 入口と実行

- CLI の入口を `cli.ts` に置く。`deno run --allow-read --allow-write cli.ts <command> ...` で動く
- `deno install -g --allow-read --allow-write --config deno.json -n epub-builder cli.ts` で、`epub-builder` というコマンドとして入れられるようにする
  - `--config deno.json` は必須とする。`deno.json` の `imports` で依存を解決するためである
  - 同じコマンドを `deno.json` のタスク `install` に置き、`deno task install` で入れられるようにする。すでに入っている場合も上書きする（`-f`）
- CI で、一時的な場所にインストールし、入れたコマンドで `--version` が動くことを確かめる
- `deno.json` のタスク `cli` から呼べるようにする
- CLI の処理は、引数、標準出力と標準エラー出力への書き込みを受け取り、終了コードを返す関数 `main` に置く。`cli.ts` を直接実行したときだけ、その終了コードでプロセスを終える
- 引数の解析は自前で書く（`src/args.ts`）。`@std/cli` には依存しない。扱うのは次の機能に限る
  - 長いオプション（`--name`）と短いオプション（`-n`）。短いオプションは長いオプションの別名として定義する
  - 値の要るオプション：`--name value`、`--name=value`、`-n value`
  - 真偽のオプション：`--name`、`-n`
  - 位置引数。`--` の後は、すべて位置引数とする
  - 知らないオプションと、値の要るオプションの値がないことの検出
  - 同じオプションを二度書いたときは、後の値を使う
- 短いオプションをまとめて書くこと（`-qe 3.0` など）と、真偽のオプションの否定（`--no-strict`）は扱わない

#### コマンド

| コマンド         | 働き                                                                                                                    |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `build [dir]`    | ディレクトリから EPUB を作り、ファイルに書く                                                                            |
| `check [dir]`    | EPUB を書かずに、読み込みと `buildEpub` の検査だけを行い、誤りと警告を出す                                              |
| `toc [dir]`      | 目次の木を、題名の入れ子で標準出力に出す。複数の版を扱うときは、版ごとに `EPUB <版>` の行を置き、その下に字下げして出す |
| `init [dir]`     | 新しい本の雛形（`book.toml`、`body/`、`meta/`、`assets/`）を作る                                                        |
| `help [command]` | 全体か、コマンドごとの使い方を出す                                                                                      |
| `version`        | CLI の版を出す                                                                                                          |

- `dir` を省いたときは、今のディレクトリとする
- コマンドを省いたとき、知らないコマンドのときは、全体の使い方を標準エラー出力に出す

#### オプション

| オプション                                    | コマンド                | 働き                                                                                                                                                                                |
| --------------------------------------------- | ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `-e`、`--epub-version <2.0.1\|3.0\|3.2\|all>` | `build`、`check`、`toc` | 作る、または調べる版。`all` はすべての版（`2.0.1`、`3.0`、`3.2`）。既定は `all`                                                                                                     |
| `-o`、`--output <path>`                       | `build`                 | 出力するファイル。既定は `<dir の名前>.epub`（今のディレクトリ）。複数の版を作るときは、拡張子の前に版を付けたファイル（`book-2.0.1.epub`、`book-3.0.epub`、`book-3.2.epub`）とする |
| `--strict`                                    | `build`、`check`        | 警告を誤りとして扱い、終了コードを 1 にする。`build` では EPUB を書かない                                                                                                           |
| `-q`、`--quiet`                               | `build`、`check`        | 警告を出さない（`--strict` と一緒に使えば、警告があるかだけを終了コードで知らせる）                                                                                                 |
| `-t`、`--title <title>`                       | `init`                  | `book.toml` の題名。既定はディレクトリの名前                                                                                                                                        |
| `-l`、`--language <lang>`                     | `init`                  | `book.toml` の言語。既定は `ja`                                                                                                                                                     |
| `-h`、`--help`                                | すべて                  | そのコマンドの使い方を出す                                                                                                                                                          |
| `-V`、`--version`                             | （コマンドなし）        | CLI の版を出す                                                                                                                                                                      |

- `--version` は CLI の版を表すため、EPUB の版は `--epub-version` で指定する
- 知らないオプション、値の要るオプションの値がない、知らない版は、使い方の誤りとする

#### 出力と終了コード

- 結果（作ったファイル、目次、使い方、版）は標準出力に、誤りと警告は標準エラー出力に書く
- 警告は `警告: <パス>[:<行>:<列>]: <メッセージ>` の形で書く（`loadBook` の既定と同じ）
- 終了コードは、成功を 0、入力の誤り（`EpubInputError`）と `--strict` での警告を 1、使い方の誤りを 2 とする
- 入力の誤りは、`誤り: <メッセージ>` の形で書く。例外の積み重ね（スタックトレース）は出さない

#### init

- `dir` がないときは作る。`dir` があって空でないときは、上書きを避けるため入力の誤りとする
- 次のファイルを作る
  - `book.toml`：`identifier`（`urn:uuid:` とランダムな UUID）、`title`、`language`。ほかのキーは注釈として書く
  - `body/01-はじめに.md`：見出し、ルビ、脚注の例
  - `meta/colophon.md`：奥付の例
  - `assets/style.css`：ルビの括弧と脚注のための最小のスタイル
- 作ったファイルの一覧を出す

#### 版の表示

- CLI の版は `src/version.ts` に置く。ADR 0015 の時点から `0.1.0` とする

### EPUB 3.2

- この ADR の上の節（ADR 0019 と ADR 0022 から写したもの）で「EPUB 3.0」「`3.0`」と書いた EPUB 3 の扱い（ナビゲーション文書、landmarks、`epub:type`、`section`、ルビ、脚注、内容文書の形、`properties` など）は、とくに断らない限り `3.2` にも当てはまる。NCX と版の値の一覧については、この節が上の節より優先する
- 出す版に `3.2` を加える。`buildEpub` と `loadBook` の `options.version`、CLI の `--epub-version` で `3.2` を指定できるようにする
- `3.2` の出力は、`3.0` の出力に次の違いを加えたものとする
  - パッケージ文書の `version` は、EPUB 3.2 の仕様どおり `3.0` と書く
  - NCX（`toc.ncx`）を作らず、manifest に載せず、spine に `toc` 属性を書かない。目次はナビゲーション文書だけで持つ
- 次は `3.0` と同じとする
  - ナビゲーション文書、landmarks、本文の文書、`epub:type`、`section`、ルビ、脚注、`dcterms:modified`
  - Kindle の `primary-writing-mode`（OPF2 の `meta`）。EPUB 3.2 では古い機能だが、Kindle が組み方向を読み取る手段はほかにないため、書き続ける
  - `loadBook` の警告（EPUB 2.0.1 の MathML と `ruby` 要素の警告は `3.2` では出さない）
- 版ごとの性格を、仕様を知らない利用者にも分かる言葉で、CLI の使い方（`help`）、README、`docs/specifications.md` に書く

| 版      | 向いている環境                                                  | 違い                                                                     |
| ------- | --------------------------------------------------------------- | ------------------------------------------------------------------------ |
| `2.0.1` | EPUB 3 に対応しない古い端末やアプリ                             | ルビは括弧書き。目次は NCX                                               |
| `3.0`   | EPUB 3 に対応する端末やアプリ。古いアプリでも目次を出したいとき | 目次はナビゲーション文書と NCX の両方                                    |
| `3.2`   | EPUB 3 に対応する、新しい端末やアプリ                           | 目次はナビゲーション文書だけ。EPUB 3.2 で古い機能とされた NCX を含まない |

- CLI の `all` は、すべての版（`2.0.1`、`3.0`、`3.2`）とする。`build`、`check`、`toc` の既定は `all` のままとし、`build` は既定で三つのファイル（`<名前>-2.0.1.epub`、`<名前>-3.0.epub`、`<名前>-3.2.epub`）を書く
- `3.0` の出力は、EPUB 3.2 で非推奨とされたもの（`guide`、`bindings`、`switch`、`trigger`、`rendition:viewport`）を書かない。いまの出力もこれらを書いていない

## 実装しないこと

- 固定レイアウト（Fixed Layout）は扱わない
- EPUB 3.1 の出力はしない。EPUB 3.2、3.3 に固有の機能（WOFF 2.0 や SFNT のフォント、外部に置いたフォントやスクリプト、`dc:subject` の `authority` と `term`、リンクの `record` など）は扱わない。版の値 `3.2` を加え、NCX の有無で `3.0` と分けることだけを行う（後述）
- EPUB 2.0.1 で `page-progression-direction` を書くことはしない。2.0.1 の仕様にない属性であり、検証で誤りになるため。縦書きは呼び出し側のスタイルシートで行う
- 音声、動画、メディアオーバーレイ、スクリプト、フォントの埋め込みの暗号化（難読化）は扱わない
- 本文の XHTML が正しいかの検査は、この ADR では行わない。呼び出し側が正しい XHTML を渡すものとする
- 特定のリーダーや配信サービスに固有の拡張（Kindle の独自のメタデータなど）は、Kindle の `primary-writing-mode` のほかは持たない
- 目次を設定で明示する手段（`SUMMARY.md` のような目次のファイルや、`book.toml` での指定）は持たない。必要になったら別の ADR で決める
- 見出しの位置で文書を分割することはしない
- 節にする見出しのレベルを設定で選ぶことはしない。すべての見出しを節にする
- 見出しの番号付け（`1.1` など）はしない
- 節の `id` が、ほかの文書からのリンクの断片識別子と合うかは確かめない
- CommonMark を拡張する記法は、ルビと脚注のほかは扱わない（GFM の表、取り消し線、傍点の記法など）。必要になったら別の ADR で決める
- モノルビ、熟語ルビ、両側ルビは扱わない
- XHTML と HTML の本文の中で、ルビと脚注の記法を解釈することはしない
- EPUB 2.0.1 で、`ruby` 要素や `ops:switch` を使ってルビを表すことはしない。`ops:switch` は仕様にあるが、対応するリーダーがほとんどない
- XHTML と HTML の本文に直接書いた `ruby` 要素を、EPUB 2.0.1 のために、Markdown のルビと同じ括弧書きの `span` などに書き換えることはしない。原稿に書いた要素を黙って別の構造に変えないため。警告を出し、EPUBCheck で誤りになる
- EPUB 2.0.1 の MathML を画像や文字に置き換えることはしない
- 後注（本の末尾に全部の注を集めること）はしない
- `.xhtml` が整形式でないときに、HTML として読み直すことはしない
- 文書ごとに適用するスタイルシートを選ぶことはしない
- フォント、音声、動画を `assets/` に置くことはしない（ADR 0003）
- スタイルシートの中身の解析や、`url()` の書き換えはしない
- 空白以外の、EPUBCheck が誤りや警告にするファイル名の文字（`"`、`*`、`:`、`<`、`>`、`?`、`\`、`|` など）の置き換えや検査はしない。必要になったら別の ADR で決める
- `buildEpub` で警告を出すことはしない。中核のモジュールは、受け取った `book` をそのまま書き出す
- 警告を例外に変える設定は持たない
- 上に挙げた要素と属性以外の参照（`srcset`、`style` 属性の中の `url()` など）は書き換えない
- 目次のページを本文の読み順に入れることはしない
- 表紙、扉、上に挙げた後付け、奥付以外の付き物（前書き、凡例、献辞など）を `meta/` に置くことはしない。本文として `body/` に置く
- 同じ種類の後付けを二つ以上置くこと、後付けをディレクトリで入れ子にすることはしない
- 書誌情報から扉の文書を自動で作ることはしない
- 変換した後の XHTML が、版ごとの仕様（要素や属性が使えるか）に合うかの検査はしない（ADR 0003）。EPUBCheck で分かる。ただし、EPUB 2.0.1 の MathML と `ruby` 要素は警告する
- EPUB 2.0.1 で、`div` などを使って構造を表すことはしない
- `epub:type` の語を、本文の内容（「プロローグ」「あとがき」などの題名）から推し量ることはしない
- `book.toml` やファイルの名前で、文書の役割を指定する手段は持たない
- landmarks と `guide` の表示名を設定で変える手段は持たない。日本語と英語のほかの言語でも英語で書く
- landmarks と `guide` に、上に挙げたほかの項目（`toc`、`preface` など）は書かない
- XHTML や HTML に直接書いた `section` 要素や `epub:type` を、書き換えたり取り除いたりすることはしない。直接書いた `section` の中の見出しは、ほかの要素の中の見出しとして扱う
- 組み方向から、スタイルシートの `writing-mode` を書くことはしない。縦書きにするスタイルは、ユーザーがスタイルシートに書く
- `primary-writing-mode` のほかの Kindle の拡張（`book-type`、`fixed-layout` など）は書かない
- EPUBCheck の呼び出しはしない。CLI の `check` は、このライブラリが検査できる範囲（読み込みの誤り、警告、`buildEpub` の検査）だけを行う
- ファイルの変更を見張って作り直すこと（watch）はしない
- 設定ファイルや環境変数でオプションを与えることはしない
- 色付きの出力、対話的な入力はしない
- `init` で既存のディレクトリに雛形を足すこと、既存のファイルを上書きすることはしない
- 配布の方法（JSR、単一の実行ファイルにすることなど）は、この ADR では決めない。インストールはリポジトリを clone した上で行う
- 版の値 `3.1` と `3.3` を加えることはしない。`3.1` は取り消された版であり、`3.3` のパッケージ文書の `version` も `3.0` である
- `3.2` の出力から、Kindle の `primary-writing-mode` を外すことはしない

## テスト設計

- 実装するときに、次をテストする
  - zip の最初の項目が、圧縮しない `mimetype` で、内容が `application/epub+zip` であること
  - 版ごとに、パッケージ文書、目次（NCX、ナビゲーション文書）、本文の文書が、必須の要素と属性を持つこと
  - 入れ子の目次、表紙、頁送りの向き、書誌情報の実体参照
- 作った EPUB を、公式の検証ツール EPUBCheck で、版ごとに検証し、誤りも警告もないことを CI で確かめる
- フィクスチャは合成データとする
- フィクスチャは、合成したディレクトリを一時ディレクトリに作って使う。著作物の文章は使わない
- TOML の解析器
  - TOML 1.0.0 の各構文（文字列の 4 種、整数と浮動小数点数の表記、日時の 4 種、配列、表、インライン表、表の配列、ドット付きのキー）を読めること
  - 誤った TOML（キーの重複、表の再定義など）が、位置を示す例外となること
  - 公開されている適合テスト（toml-test、MIT）のケースを、ライセンスの表記とともに取り込んで使うことを検討する
- 書誌情報
  - `book.toml` を書誌情報に読み、必須のキーがない、知らないキーがある、型が違う、ローカル日時の `modified`、ない `cover_image`、ファイルがない場合に例外となること
- 並び
  - 符号位置の順になること。連番の桁がそろわない場合（`10-` と `2-`）、サロゲートペアを含む名前、NFD の名前を含めて確かめる
- ファイルの構成の誤り
  - 拡張子を除いて同じ名前のファイル、知らない拡張子（`body/` と `assets/`）、空の `body/`、空のサブディレクトリ、`meta/` の知らない名前が例外となること
  - `.` で始まるファイルとディレクトリが無視されること
- 変換
  - Markdown、`.xhtml`、`.html` が、それぞれ XHTML の構文で出ること。空要素が閉じられ、名前付きの文字参照が文字になり、`epub:type` が名前空間付きの属性になること
- ルビ
  - `｜` と `|` のある書き方、漢字だけの親文字を省いた書き方（`々` などを含む）が、版ごとの形で出ること。EPUB 2.0.1 では `ruby` 要素が出ないこと
  - 空の親文字やルビ、`《…》` の続かない `|`、`\《`、コードスパンとコードブロックの中が、文字のまま出ること
  - 強調の中、リンクの文字、見出し、脚注の本文の中でルビが使えること
- 脚注
  - 参照と注の本文が、版ごとの形で、最初に参照した順の番号で出ること
  - 一つの注を二度参照したときの ID と戻りのリンク
  - 複数の段落からなる注の本文
  - 定義のない参照、参照されない定義、ラベルの重なる定義、ID の衝突、注の本文の中の参照が例外となること
- 題名
  - ルビと脚注の参照を含む見出しから、親文字だけの題名が取り出されること
  - Markdown の中の生の HTML が、`.html` と同じ規則で変換されること
  - 整形式でない `.xhtml`、DOCTYPE や知らない実体参照を含む `.xhtml` が例外となること
  - 上に挙げた XHTML に直せない場合が、それぞれ例外となること
  - 自前の XML の解析器と書き出し器で、読んで書き出した結果を読み直すと同じ木になること
- 参照の書き換え
  - 本文の深さが違う文書から `assets/` の画像と、ほかの文書（断片識別子付き）を指す参照が、EPUB の中の正しい相対パスになること。パーセントエンコードを含む名前も確かめる
  - 外部の画像、`/` で始まる参照、範囲の外、ないファイルを指す参照が例外となること。外部へのリンクと `#` だけの参照が書き換えられないこと
- 目次
  - 題名が、見出し、ファイルの名前（連番を除く）、連番だけの名前の順で決まること
  - サブディレクトリが入れ子の項目になり、`index` の有無で行き先と子が変わること
  - 読み順が表紙、扉、本文、後付け（表の順）、奥付となり、表紙と扉が目次に入らず、後付けが本文の後に、奥付が目次の最後に入ること
  - `meta/` の後付けの名前が、表のとおりに受け付けられ、ほかの名前が例外になること
- ファイル名の空白
  - 空白類（ASCII の空白、全角空白、ノーブレークスペース、タブ）を含むファイルとディレクトリの名前が `_` に置き換わり、本文の中の参照（パーセントエンコードしたものを含む）と `cover_image` が置き換えた後のパスを指すこと
  - 置き換えた結果が重なる場合に例外となること
  - 名前を置き換えたファイルごとに `renamed-file` の警告が出ること
- EPUB 2.0.1 で使えない要素の警告
  - EPUB 2.0.1 で、`.xhtml`、`.html`、Markdown の生の HTML の `math` 要素と `ruby` 要素が、ファイルのパスと行と列を持つ警告になり、例外にならず、要素がそのまま出ること。EPUB 3.0 では警告が出ないこと
  - `onWarning` を渡さないとき、`console.warn` に書くこと
- 節
  - 見出しのレベルからの入れ子（レベルが飛ぶ場合、最初の見出しより小さいレベルが後に来る場合を含む）
  - 文書の題名に使った見出しが節にならないこと
  - 見出しの `id` を使うこと、なければ `sec-<番号>` を付けること、本文にある `id` を避けること
  - `index` の節が、ディレクトリの子の項目より前に来ること
  - 奥付の節が目次に入り、表紙と扉の見出しが入らず、表紙と扉の見出しに `id` を付けないこと
  - 脚注の欄の中の見出しと、空の見出しが節にならないこと
  - 節の題名から、ルビの読みと脚注の参照が除かれること
  - `buildEpub` が、節を NCX とナビゲーション文書に、文書の中の断片識別子付きの行き先で書き、`playOrder` を目次の順に振ること
  - `buildEpub` が、本文のない章の `sections`、空の `id`、本文にない `id` を例外にすること
- `loadBook` で読んだ本を `buildEpub` で版ごとに EPUB にし、EPUBCheck を通ること（ADR 0003）。`test/fixtures/` のフィクスチャにはルビ、脚注、空白類を含む名前の画像、節を含め、CI で版ごとに EPUBCheck に掛ける
- `buildEpub` が、EPUB 3.0 では `epubType` を `body` の `epub:type` に書き、EPUB 2.0.1 では書かないこと
- `buildEpub` が、空白だけの `epubType` と XML で使えない文字を含む `epubType` を例外にすること
- `loadBook` が、どちらの版でも、表紙、扉、部の扉、深いディレクトリの扉、章、後付け、奥付に、表のとおりの `epubType` を付けること
- 節の `section` 要素
  - 見出しのレベルによる入れ子と、レベルが飛ぶ場合
  - 文書の題名とそれより前の内容が囲まれないこと
  - 脚注の欄が `section` の外に出ること
  - ほかの要素の中の見出しが囲まれず、目次の節には残ること
  - 空の見出しなど、節にしない見出しが `section` を始めないこと
  - EPUB 2.0.1 では囲まないこと
- landmarks
  - EPUB 3.0 のナビゲーション文書に、表紙、扉、本文、後付け、後付けのそれぞれ、奥付の項目が、この順で、行き先がある項目だけ書かれること。目次の項目がないこと
  - `bodymatter` を含む章がないとき、最初の章の文書を本文の始まりにすること
  - 言語が `ja` のときと、それ以外のときの表示名
  - EPUB 2.0.1 では書かないこと
- guide
  - EPUB 2.0.1 のパッケージ文書に、表紙、扉、本文、後付けのそれぞれ（`other.` の型を含む）、奥付の項目が、この順で、行き先がある項目だけ書かれること。目次の項目がないこと
  - `bodymatter` を含む章がないとき、最初の章の文書を本文の始まりにすること
  - 言語が `ja` のときと、それ以外のときの `title`
  - EPUB 3.0 では書かないこと
- フィクスチャから作った EPUB が、どちらの版でも EPUBCheck を誤りも警告もなく通ること
- primary-writing-mode
  - `buildEpub` が、どちらの版でも、`primaryWritingMode` をパッケージ文書の `meta` に書き、ないときは書かないこと
  - `buildEpub` が、知らない値と、頁送りの向きと食い違う値を例外にすること
  - `loadBook` が、`primary_writing_mode` を読むこと、ないときに `page_progression_direction` から決めること、どちらもないときに持たないこと、食い違うときと知らない値を例外にすること
  - 作った EPUB が EPUBCheck を通ること
- `main` に引数と、出力を受け取る関数を渡して試す。ファイルは一時ディレクトリに作る
- `build`：既定ですべての版を、版を付けた名前で書くこと、`-e` で一つの版だけを書くこと、既定の出力先、`-o`、`all` での二つのファイル、作った EPUB の版、警告の出力、`--strict` で書かないこと、`--quiet`
- `check`：誤りのないとき 0、入力の誤りのとき 1 と `誤り:` の出力、警告の出力、`--strict` で 1
- `toc`：目次の木の入れ子と題名、既定ですべての版を版ごとの見出しの下に出すこと、`-e` で一つの版だけを見出しなしで出すこと
- `check`：既定ですべての版を調べること
- `init`：作るファイルとその中身、作った雛形が `check` を通ること、空でないディレクトリを誤りにすること、`--title` と `--language`
- `help`：全体、コマンドごと、`-h` と `--help`、知らないコマンド
- `version` と `--version`
- `deno task install` と同じコマンドで一時的な場所にインストールしたコマンドが動くこと（CI）
- 引数の解析：上に挙げた機能のそれぞれ（長いと短いオプション、`=` の形、値のないオプション、知らないオプション、`--` の後の位置引数、二度書いたオプション）。`@std/cli` の `parseArgs` のテストを参考に、該当する場合を移す
- 使い方の誤り：コマンドなし、知らないコマンド、知らないオプション、知らない版、値のないオプション、余分な引数で 2
- EPUB 3.2
  - `buildEpub`、`loadBook`、CLI が版の値 `3.2` を受け付け、CLI の `all` が `2.0.1`、`3.0`、`3.2` になること。`build` が既定で三つのファイルを書くこと
  - `3.2` の出力のパッケージ文書の `version` が `3.0` であり、NCX を含まず（ファイル、manifest、spine の `toc` 属性のどれも）、ナビゲーション文書と landmarks を含むこと
  - `3.2` の出力が、NCX のほかは `3.0` の出力と同じであること（本文の文書、ナビゲーション文書、`primary-writing-mode`）
  - `3.0` の出力が、`guide`、`bindings`、`switch`、`trigger`、`rendition:viewport` を含まないこと
  - フィクスチャから作った `3.2` の EPUB が、EPUBCheck を誤りも警告もなく通ること
  - CLI の使い方に、三つの版の向いている環境が書かれていること

## トレードオフ

- 一つの入力から両方の版を出すため、片方の版にしかない機能は、もう片方では無視するか、別の手段で表すことになる
- EPUB 3.0 にも NCX を入れるため、出力は少し大きくなる。その代わり、古いリーダーでも目次が使える
- 本文の XHTML を検査しないため、呼び出し側の誤りは EPUBCheck で初めて分かる
- 並びを文字コード順に限るため、連番の桁をそろえる手間がユーザーにかかる。その代わり、並びの規則が一つで、ファイルの一覧からそのまま予想できる
- 目次を設定で明示できないため、構成と異なる目次は作れない
- すべての見出しを節にするため、目次が深く長くなる。見出しの多い原稿では、リーダーの目次が読みにくくなることがある。必要になったら、レベルを選ぶ設定を別の ADR で決める
- 見出しに `id` がない原稿では、EPUB の本文に `sec-<番号>` の `id` が加わる。見出しを足したり減らしたりすると、後ろの見出しの `id` が変わる
- 目次の項目の行き先に断片識別子が入るため、NCX の `playOrder` は同じ文書の中でも節ごとに別の値になる
- 知らないキーや拡張子を例外にするため、ほかの道具と同じディレクトリを共有しにくい。カメラが付ける `.JPG` も名前を変える必要がある
- XHTML と HTML を拡張子で分け、中身から推測しないため、`.xhtml` に HTML の書き方をすると例外になる。その代わり、XHTML の書き損じが HTML の回復の規則で黙って別の構造に直されることがない
- EPUB 2.0.1 ではルビが括弧書きになり、ルビとして組まれない。スタイルシートで小さくしても、親文字の上や横には載らない
- EPUB 2.0.1 で MathML や `ruby` 要素を使った EPUB は、警告が出たうえで作られ、EPUBCheck で誤りになる。ADR 0003 の「誤りも警告もないこと」は、`mathml-in-epub-2` と `ruby-in-epub-2` の警告を出さない入力に対してだけ保証する
- EPUB の中のファイル名が、原稿のファイル名と変わることがある。スタイルシートの `url()` で空白を含む名前を指していると、参照が切れる。警告で知らせるが、直すのはユーザーである
- 警告の既定の出力先が標準エラー出力のため、ライブラリとして使う側には余計な出力になることがある。その場合は `onWarning` で受け取る
- ルビの記法は Web 小説の書き方に合わせたため、CommonMark の中では独自の記法になり、ほかの Markdown の道具では文字のまま表示される
- 漢字の並びを親文字とする省略の書き方は、`東京都庁《ちょう》` のように、親文字が意図より長くなることがある。その場合は `｜` を書く必要がある
- 脚注を文書ごとに置き、`loadBook` が版を受け取るため、同じ `book` から両方の版を出すには `loadBook` を二度呼ぶ必要がある
- `loadBook` は unified 系のライブラリに依存する。中核のモジュールは依存しないが、`loadBook` を使う側は依存を取り込むことになる
- TOML と XML の解析器、XHTML の書き出し器を自前で書くため、実装と保守の手間が増える。その代わり、依存が減り、EPUB に合わせた出力を制御できる
- すべてのスタイルシートをすべての文書に適用するため、表紙だけに効かせたいスタイルは、セレクタで書き分ける必要がある
- 内容文書の名前を読み順の番号にするため、本文を一つ足すと、後ろの文書の名前が変わる。EPUB の中の名前はユーザーが直接書かないため、影響は出力の差分が大きくなることにとどまる
- EPUB 2.0.1 と EPUB 3.0 で、本文の構造が違う。同じ原稿でも、EPUB 3.0 には `section` 要素が加わる
- 見出しの直後から次の見出しまでを機械的に囲むため、原稿の意図と違うまとまりになることがある。たとえば、節の後に節に属さない段落を置きたい場合は表せない
- 役割の語は、ディレクトリの深さと文書の種類だけで決める。プロローグやあとがきも `chapter` になる
- landmarks の表示名は日本語と英語だけで、ほかの言語の本では英語になる
- landmarks と `guide` から目次へ移ることはできない。リーダーは目次をナビゲーション文書の `toc` や NCX から出す
- `loadBook` の `epubType` が EPUB 2.0.1 でも付くため、EPUB 2.0.1 を作るときに `book` の値を見ると、本文に書かれない `epubType` を持っている
- `section` で囲むため、`body > h2 + p` のように、本文の直下の要素の並びを前提にしたスタイルシートのセレクタは、EPUB 3.0 では効かなくなる
- Kindle に固有の `meta` を入れるため、ほかのリーダーには意味のない情報が加わる
- `page_progression_direction` が `rtl` の本を `vertical-rl` とみなすため、右から左の横書きの本（アラビア語など）では、`primary_writing_mode` を書く必要がある
- インストールには `--config deno.json` が要るため、リポジトリの外からファイルの URL だけでインストールすることはできない
- 既定ですべての版を扱うため、一つの版だけが欲しいときは `--epub-version` を付ける必要がある。`check` と `toc` は、すべての版を読み込む分だけ時間がかかる
- `toc` は、版によって目次が同じでも、版ごとに出す
- `--version` を CLI の版に使うため、EPUB の版のオプションの名前が長くなる（短い名前は `-e`）
- `check` は EPUBCheck を呼ばないため、`check` を通っても EPUBCheck で誤りになることがある（直接書いた XHTML の誤りなど）
- 引数の解析を自前で書くため、`@std/cli` が扱う書き方（短いオプションのまとめ書き、否定など）の一部は使えない
- `3.2` は `3.0` と NCX の有無だけが違うため、多くの環境ではどちらでも同じように読める。違いを使い方とドキュメントで説明する必要がある
- `3.2` の本は NCX を含まないため、EPUB 2 にしか対応しないアプリでは目次が出ない。その場合は `3.0` か `2.0.1` を使う
- `build` の既定のファイルが二つから三つに増える
- `3.2` でも、EPUB 3.2 で古い機能とされた OPF2 の `meta`（`primary-writing-mode`）を書く
