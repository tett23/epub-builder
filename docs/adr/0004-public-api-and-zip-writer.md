# ADR 0004: 公開 API を、本を表す値を受け取って EPUB のバイト列を返す一つの関数とし、zip は自前で書く

ステータス: 採択

## 文脈

ライブラリを使う側（epubize など）は、データベースから読んだ本文や画像を渡して、EPUB のファイルを得たい。
EPUB は zip だが、`mimetype` を最初に圧縮せずに置くという制約がある（ADR 0003）。
Deno には、zip を書く標準のライブラリがない。一方、Web 標準の `CompressionStream`（`deflate-raw`）で圧縮はできる。

## 実装すること

- 公開する関数は `buildEpub(book, options)` とし、EPUB のファイルの中身を `Uint8Array` で返す。ファイルに書くかどうかは呼び出し側が決める
  - `options.version` に `"2.0.1"` か `"3.0"` を渡す（ADR 0003）
- `book` は次を持つ値とする。型は TypeScript で公開する
  - 書誌情報：識別子、題名、言語、著者（複数可）、出版者、説明、更新日時（EPUB 3.0 の `dcterms:modified` に使う。省略したら呼んだ時刻）
  - 頁送りの向き（`ltr` か `rtl`）
  - スタイルシート：パスと内容
  - 本文：章の並び。各章は題名、XHTML の本文（`body` の中身）、使うスタイルシート、入れ子の子を持てる
  - 画像：パス、メディアタイプ、バイト列。どれを表紙にするか
- パッケージ文書の中の ID とファイルの名前は、ライブラリが決める
- 入力の誤り（必須の書誌情報がない、パスが重なる、知らないメディアタイプなど）は、EPUB を作る前に、理由を示す例外で知らせる
- zip は自前で書く。外部の依存は持たない
  - 圧縮は `CompressionStream("deflate-raw")`、CRC-32 は自前で計算する
  - `mimetype` は最初に、圧縮せず（stored）、追加の項目なしで書く
  - ほかの項目は deflate で圧縮する。圧縮した方が大きくなる項目は stored にする
  - ファイル名は UTF-8 とし、その旨のフラグを立てる
  - ZIP64 には対応しない
- 配布の方法（JSR に公開するかなど）は、実装ができたときに決める

## 実装しないこと

- ストリームで少しずつ書き出すことはしない。全体をメモリ上に作る
- zip の暗号化、ZIP64 は扱わない
- 外部の zip のライブラリは使わない

## テスト設計

- 実装するときに、次をテストする
  - 公開する関数が、版ごとに EPUB を返すこと
  - 入力の誤りを、EPUB を作る前に例外で知らせること
  - zip の書き出し：作った zip を読み戻し、項目の名前、順序、圧縮の方法、CRC-32、中身が合うこと。CRC-32 を既知の値と比べること
  - 作った EPUB が EPUBCheck を通ること（ADR 0003）

## トレードオフ

- zip を自前で書くため、実装と保守の手間が増える。その代わり、依存がなく、`mimetype` の置き方を確実に制御できる
- 全体をメモリ上に作るため、挿絵の多い大きな本ではメモリを多く使う
- ZIP64 に対応しないため、4 GiB を超える EPUB は作れない。小説ではまず起きない
